# Турнир Unmatched — сайт

Статичный сайт (HTML/CSS/JS, без сборки и бэкенда). Все данные о турнире правятся руками в одном файле.

## Как обновлять данные

Всё редактирование — в [js/data.js](js/data.js):

- `characters` — словарь персонажей (`slug: { name, image }`).
- `players` — словарь игроков (сейчас Рома и Глеб).
- `cards` — пул из 15 карт-локаций, которые случайно достаются матчам.
- `cardDrawOrder` — список id матчей в порядке, в котором им реально доставалась карта (не порядок сетки!). Пополняется вручную при заполнении `card` у матча.
- `matches` — все 31 матч сетки (16 игр в 1/16, 8 в 1/8, 4 в 1/4, 2 в 1/2, финал). Связи между раундами (`nextMatchId`/`nextMatchSlot`) уже прописаны и трогать их не нужно.

Как заполнять по ходу турнира — подробно расписано комментариями прямо в начале `js/data.js`. Коротко:

1. Пара определилась → вписать `slotA.character`/`slotB.character`, `status: "scheduled"`, при желании `scheduledDate`.
2. Карту, то, кто из игроков за кого играет, и кто ходит первым, определяете сами и вписываете сразу в `data.js`: `card`, `slotA.player`/`slotB.player`, `firstMove` ("A" или "B"). Для 1/16 firstMove не нужен — там жёсткое правило (всегда slotA); начиная с 1/8 первый ход и распределение игроков считаются по отдельному алгоритму (кто был первым/вторым и кто за кого играл в предыдущем матче каждого персонажа — если по обоим совпадает, тай-брейк через хеш). Не дожидаясь самой игры — можно сделать это заранее. Пока `status` матча не `"completed"`, эти данные на сайте показываются под спойлером («Показать»), случайно зашедший их не увидит раньше времени; как только матч отмечен сыгранным, спойлер сам исчезает.
3. Матч сыгран → `status: "completed"`, `winner: "A" | "B"`, заполнить `stats`.
4. Победителя нужно вручную вписать в `slotA`/`slotB` следующего матча (id из `nextMatchId`, слот из `nextMatchSlot`) — автоматического переноса нет, это осознанно, чтобы не плодить скрытую логику.

После правки файла просто открываете `index.html` — изменения сразу видны.

### Как работает розыгрыш карт

15 карт раздаются без повторов, пока не будут разыграны все — то есть карта, доставшаяся в матчах 1–15, не может выпасть снова, пока не сыграны все 15; в матчах 16–30 колода «перетасовывается» заново, и так далее. Сайт вычисляет это сам по `cardDrawOrder` (просто считает последние N записей от начала текущего цикла по 15) — поэтому важно дописывать туда id каждого матча сразу после розыгрыша, иначе следующий подбор насчитает пул неверно.

## Картинки и шрифт

- `assets/fonts/bebasneuecyrillic.ttf` — шрифт уже подключён.
- `assets/characters/<slug>.jpg` — портрет персонажа (путь задаётся в `characters` в data.js). Пока файла нет — на сайте автоматически показывается плейсхолдер с первой буквой имени, вёрстка не ломается.
- `assets/cards/<slug>.*` — изображение карты (путь задаётся в `cards` в data.js), тот же принцип с плейсхолдером.
- `assets/cardbacks/<slug>.*` — рубашки колод по каждому персонажу, уже скачаны; куда именно их выводить на сайте — пока не решено.

Просто кладите файлы с нужными именами в соответствующие папки — ничего больше делать не нужно.

## Деплой на GitHub Pages

1. Создать репозиторий на GitHub и запушить в него содержимое этой папки.
2. В репозитории: Settings → Pages → Source → Deploy from a branch → выбрать `main` и `/ (root)`.
3. Через минуту-две сайт будет доступен по адресу вида `https://<username>.github.io/<repo>/`.

Дальше любое обновление — это просто `git add`, `git commit`, `git push`: сборка не требуется, GitHub Pages отдаёт статические файлы как есть.
